== DGGS Entity Type Requirements

`Cell` is the entity type of the <<conformance_class_cell>> Conformance Class. This clause also defines the additional direct relations from `Observation`, `Datastream`, and `MultiDatastream` that this Standard adds. The SensorThings entity types of <<OGC18-088>> remain as defined in that Standard.

NOTE: Please be aware that all of the Requirements Classes in this section are part of the Conformance Class <<conformance_class_cell>>.

[[cell]]
=== Requirements Class *Cell*

The `Cell` entity represents one zone of the Discrete Global Grid System deployed by the implementation. It is used to spatially group observations: an `Observation`, a `Datastream`, or a `MultiDatastream` linked to a `Cell` belongs somewhere in that cell.

The `zoneId` property is the string representation of the cell identifier in the deployed grid system. It SHALL be identical to `@iot.id`. For H3, `zoneId` is the hexadecimal H3 index. For Geohash, `zoneId` is the geohash string.

The `@iot.id` of a `Cell` SHALL be a CharacterString, encoded as a JSON string. That encoding ensures that a JavaScript client can parse the identifier without issues that BigInt indexes would cause.

The `system` property identifies the deployed grid system. Its value SHALL be the `gridSystem` value advertised on the landing page as specified in <<grid-system>>.

The `zoneLevel` property is the hierarchical resolution of the zone. A smaller value is a coarser zone. A larger value is a finer zone. `zoneLevel` is optional because some grid systems encode the level in the identifier.

The `boundary` property is the geometry of the DGGS zone. It uses the same encoding rules as `Location/location` and `FeatureOfInterest/feature` in <<OGC18-088>>. The `encodingType` property indicates the encoding of `boundary`. If `boundary` is present, `encodingType` SHALL be present.

[[cell-id-type]]
[requirement]
====
[%metadata]
identifier:: {identifier}/req/cell/id-type

The `@iot.id` of a `Cell` SHALL be of type CharacterString. In the JSON encoding, `@iot.id` SHALL be a JSON string, not a JSON number. This requirement ensures that a JavaScript client can parse the identifier without loss of precision.

The `zoneId` of a `Cell` SHALL be identical to `@iot.id`.
====

[requirement]
====
[%metadata]
identifier:: {identifier}/req/cell/consistency

Datastreams that are linked to the same `Cell` and that observe the same `ObservedProperty` SHALL use the same `unitOfMeasurement`.

MultiDatastreams that are linked to the same `Cell` and that represent the same aggregate of the same base `ObservedProperty` SHALL use the same `ObservedProperties` array and the same `unitOfMeasurements` array.
====

  "Children@iot.navigationLink": "Cells('891f8d7a49bffff')/Children",

  "zoneId": "891f8d7a49bffff",
  "zoneLevel": 9,
  "system": "H3",
  "encodingType": "application/geo+json",

[[cell]]
=== Requirements Class *Cell*

The `Cell` entity represents one zone of the Discrete Global Grid System deployed by the implementation. It is used to spatially group observations: del:[an `Observation`, a `Datastream`, or a `MultiDatastream` linked to a `Cell` belongs somewhere in that cell.] add:[the observations of a `Datastream` or a `MultiDatastream` linked to a `Cell` belong somewhere in that cell.]

The `zoneId` property is the string representation of the cell identifier in the deployed grid system. It is identical to `@iot.id`. For H3, `zoneId` is the hexadecimal H3 index. For Geohash, `zoneId` is the geohash string.

The `@iot.id` of a `Cell` is a CharacterString, encoded as a JSON string. That encoding ensures that a JavaScript client can parse the identifier without issues that BigInt indexes would cause.

The `system` property identifies the deployed grid system. Its value is the `gridSystem` value advertised on the landing page as specified in <<grid-system>>.

The `zoneLevel` property is the hierarchical add:[level of] resolution of the zone. A smaller value is a coarser zone. A larger value is a finer zone. `zoneLevel` is optional because some grid systems encode the level in the identifier.

The `boundary` property is the geometry of the DGGS zone. It uses the same encoding rules as `Location/location` and `FeatureOfInterest/feature` in <<OGC18-088>>. The `encodingType` property indicates the encoding of `boundary`. If `boundary` is present, `encodingType` is present.

add:[The implementation may delete an orphan `Cell`. Whether the implementation does so is advertised as `removeOrphanCells` on the landing page.]

[requirement]
====
[%metadata]
identifier:: {identifier}/req/cell/id-type

The `@iot.id` of a `Cell` SHALL be of type CharacterString. In the JSON encoding, `@iot.id` SHALL be a JSON string, not a JSON number. This requirement ensures that a JavaScript client can parse the identifier without del:[loss of precision] add:[the nedd to support BigInteger].

[[grid-system]]
[requirement]
====
[%metadata]
identifier:: {identifier}/req/grid-system

The implementation SHALL del:[provide] add:[include] a JSON object in the `serverSettings` object on the landing page (the root URI) with the name `{identifier}/conf/core`. That object SHALL contain:

* a property `gridSystem` whose value is a CharacterString that identifies the Discrete Global Grid System deployed by the implementation (for example `H3` or `GEOHASH`);
* a property `coarsestZoneLevel` whose value is an Integer that identifies the coarsest zone level at which the implementation materializes parent cells;
* a property `finestZoneLevel` whose value is an Integer that identifies the finest zone level at which the implementation materializes cells.

The advertised `finestZoneLevel` SHALL be greater than or equal to the advertised `coarsestZoneLevel`.

Every `Cell/system` value SHALL be identical to the advertised `gridSystem`.
====

[[cells-boundary]]
[requirement]
====
[%metadata]
identifier:: {identifier}/req/cells-boundary

The JSON object with the name `{identifier}/conf/core` in the `serverSettings` object on the landing page (the root URI) SHALL contain a member del:[`cellCreateBoundary`] add:[`cellsBoundary`] whose value is a JSON object. That JSON object SHALL contain:

* a property `encodingType` whose value is a media type as used for `Location/location` and `FeatureOfInterest/feature` in <<OGC18-088>> (for example `application/geo+json`);
* a property `boundary` whose value is a geometry that defines del:[the area within which a `Cell` can be created] add:[the area within which the implementation materializes `Cell` entities].

The advertised `boundary` SHALL be a Polygon or a MultiPolygon. A Polygon MAY be a simple polygon (one exterior ring and no holes). A Polygon or a MultiPolygon MAY contain holes (interior rings).

add:[`cellsBoundary` is the area within which the implementation materializes cells. The implementation materializes a `Cell` only when that `Cell` is spatially within `cellsBoundary`. `cellsBoundary` is used to prevent flooding of the database with too many `Cell` entities.]

add:[The default `cellsBoundary` covers "the world".]
====

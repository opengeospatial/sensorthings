[[staplus-auth]]
== STAplus Authentication Requirements


=== Overview

To regulate access to entities using CRUD operations, implementations may wish to use information from user / client application authentication to make access control decisions. 

In addition, some implementations may wish to link the authentication identifier (e.g., `REMOTE_USER`) with the `Party/authId`. Therefore, the STAplus authentication must provide service-wide unique user identifiers.

The STAplus authentication SHALL provide a user identifier add:[that is] permanent for del:[same] add:[a given] user del:[but different for each user] add:[and unique across users].

[requirement]
====
[%metadata]
identifier:: {identifier-corrigendum}/req/authentication/id-read

The STAplus implementation SHALL ensure that the `Party/authId` property is add:[not] exposed in any responseadd:[, including MQTT payloads,] and can add:[not] be used in STA operators such as `$select` add:[or `$expand` or `$orderby`] unless the authenticated user is represented by the `Party`. add:[The property SHALL NOT be used in `$filter` except as specified in `{identifier-corrigendum}/req/authentication/me`.] add:[An MQTT message SHALL NOT contain `Party/authId` unless the MQTT client is authenticated as the user represented by that `Party`.]
====

[requirement]
====
[%metadata]
identifier:: {identifier-corrigendum}/req/authentication/id-create

The STAplus implementation SHALL overwrite any existing value and SHALL set the `Party/authId` property with add:[a unique identifier based on] the user's identification value provided by the authentication (e.g., `REMOTE_USER`). add:[The implementation SHALL set `Party/@iot.id` to a random identifier that is not correlated to the user identification.]
====

[requirement]
====
[%metadata]
identifier:: {identifier}/req/authentication/id-update

The STAplus implementation SHALL ensure that the `Party/authId` property cannot be changed (ensure read-only).
====

[requirement]
====
[%metadata]
identifier:: {identifier}/req/authentication/id-delete

The STAplus implementation SHALL ensure that the `Party/authId` property cannot be deleted.
====

[[req-authentication-me]]
[requirement]
====
[%metadata]
identifier:: {identifier-corrigendum}/req/authentication/me

add:[The STAplus implementation SHALL support the parameterless OData function `me()` that evaluates to the authenticated user.]

add:[The implementation SHALL accept a `$filter` that compares `authId` with `me()`, including `Parties?$filter=authId eq me()` and a navigation path such as `Datastreams?$filter=Party/authId eq me()`. For `Parties?$filter=authId eq me()`, the response SHALL contain the `Party` whose `authId` is associated with the authenticated user. If no such `Party` exists, the implementation SHALL return HTTP 200 with an empty collection.]

add:[An unauthenticated request that applies `me()` SHALL be rejected with HTTP 404.]
====

NOTE: add:[<<req-authentication-me>> is an additional requirement of this corrigendum.]

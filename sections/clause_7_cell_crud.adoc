=== Overview

This clause defines the Read of `Cell` via HTTP GET and the restrictions on Create, Update, and Delete of a `Cell`.

A Discrete Global Grid System is useful only if every `Cell` with a given identifier is the same zone of the same system at the same level. del:[Create, Update, and Delete of a `Cell` are therefore limited to the implementation itself and to an administrator.]

add:[A client cannot create a `Cell`. A client cannot update a `Cell`, and a client cannot delete a `Cell`. The implementation instantiates a `Cell` when a reference names a `Cell` that does not yet exist.]

del:[A client does not create a `Cell` by posting a `Cell` representation to the `Cell` entity type. A client does not create a `Cell` inline in the body of an `Observation`, a `Datastream`, or a `MultiDatastream`. A client creates a `Cell` by reference only, using the link-to-existing-entities pattern of <<OGC18-088>>:] add:[A client can always assume that a `Cell` exists. A client therefore always uses a reference to a `Cell`, using the link-to-existing-entities pattern of <<OGC18-088>>. A client does not post a `Cell` representation to the `Cell` entity type, and a client does not send an inline `Cell` representation in the body of a `Datastream` or a `MultiDatastream`:]

[source,json]
----
"Cell": { "@iot.id": "309f09" }
----

del:[If the referenced `Cell` does not exist, the implementation creates it from a template: `zoneId` is identical to `@iot.id`, and the remaining properties are filled from the advertised grid system. The implementation also creates every parent `Cell` down to the advertised `coarsestZoneLevel`.] add:[If the referenced `Cell` does not exist, the implementation instantiates that `Cell` from a template: `zoneId` is identical to `@iot.id`, and the remaining properties are filled from the advertised grid system. The implementation does not instantiate a parent `Cell`.]

An instantiated `Cell` is spatially within the advertised del:[cell-create boundary] add:[cells boundary]. add:[The cells boundary is the area within which the implementation materializes cells, as specified in <<cells-boundary>>.]

[requirement]

[%metadata]
identifier:: {identifier}/req/read/entity

To read a `Cell` entity or the `Cell` entity type, the client SHALL send an HTTP GET request to that entity or the URL of the `Cell` entity type as defined in <<OGC18-088>>. The URL of the `Cell` entity type SHALL use the entity-set name `Cells`. The landing page `value` array specified in <<OGC18-088>> §9.2.1 SHALL include an element for the `Cells` entity set.

If the target URL for the `Cell` entity type is a navigationLink, the entity is automatically linked to the entity or entities represented by the navigationLink.

Upon successful completion, the response SHALL contain the representation of the entity or entities.

NOTE: A read of a del:[non-existing] add:[non-materialized] `Cell` SHALL return HTTP 404, compliant with <<OGC18-088>>.

== Preface

This Standard extends <<OGC18-088>> (OGC SensorThings API Part 1: Sensing Version 1.1) with the `Cell` entity type so that observations can be spatially grouped into Discrete Global Grid System (DGGS) zones. A `Cell` represents a zone of a deployed grid system such as H3 or Geohash. del:[An `Observation`, a `Datastream`, and a `MultiDatastream` may each be linked to zero-or-one `Cell`. That link expresses that the observation or stream belongs somewhere in that cell.] add:[A `Datastream` and a `MultiDatastream` may each be linked to zero-or-one `Cell`. That link expresses that the observations of the stream belong somewhere in that cell.]

The extension is fully backwards compatible with <<OGC18-088>>. An implementation that conforms to this Standard also conforms to the SensorThings Sensing data model of <<OGC18-088>>. This extension can also be used together with <<OGC22-022r2>> (STAplus 1.0.1).


[abstract]
== Abstract

The OGC SensorThings API Extension: del:[DGGS] add:[Spatio-temporal Aggregations] 1.0 Standard specifies a backwards-compatible extension to <<OGC18-088>>. The extension can also be used with <<OGC22-022r2>> (STAplus 1.0.1).

<<OGC18-088>> associates an observation with `Location/location` of a `Thing` and with `FeatureOfInterest/feature`. Neither of those geometries groups observations by a DGGS zone. This Standard adds the `Cell` entity so that observations can be spatially grouped: del:[an observation linked to a `Cell`, or an observation of a `Datastream` or `MultiDatastream` linked to a `Cell`,] add:[an observation of a `Datastream` or `MultiDatastream` linked to a `Cell`] was made somewhere in that cell. The optional `Cell/boundary` property is the geometry of that zone.

The `Cell` entity records the zone identifier (`zoneId`), an optional zone level (`zoneLevel`), the grid system (`system`), the optional zone geometry (`boundary`) with its `encodingType`, and optional `properties`. `Cell/boundary` uses the same encoding rules as `Location/location` and `FeatureOfInterest/feature` in <<OGC18-088>>. A `Cell` has zero-or-one parent `Cell` and zero-to-many children, so the DGGS hierarchy is navigable through the SensorThings API. del:[`Observation`, `Datastream`, and `MultiDatastream` each have] add:[`Datastream` and `MultiDatastream` each have] a zero-or-one association to `Cell`. add:[An `Observation` is linked to a `Cell` only through its `Datastream` or `MultiDatastream`.]

This Standard defines del:[seven] add:[five] Conformance Classes. The mandatory del:[`Cell`] add:[`Core`] Conformance Class defines the data model extension. The del:[<<cell,Cell>>] add:[<<system,System>>] Requirements Class requires the implementation to advertise the deployed grid system (for example H3 or Geohash) on the landing page and to advertise a Polygon or MultiPolygon that defines del:[the area within which a `Cell` can be created] add:[the area within which the implementation materializes cells]. The mandatory del:[`Cell CRUD`] add:[`Cell`] Conformance Class defines the Read of `Cell` via HTTP GET. del:[It restricts Create, Update, and Delete of a `Cell` to the implementation itself and to an administrator, so that cells remain uniform; a cell is created by reference only from an `Observation`, a `Datastream`, or a `MultiDatastream` (`{"@iot.id": "309f09"}` creates the `Cell` with `zoneId` equal to `"309f09"` from a template), and inline creation is rejected.] add:[A client cannot create, update, or delete a `Cell`. A client can assume that a `Cell` exists and always uses a reference (for example `{"@iot.id": "309f09"}`). The implementation instantiates that `Cell` if it does not exist, with `zoneId` equal to the referenced `@iot.id`.] A del:[created] add:[materialized] `Cell` is within the advertised del:[cell-create boundary] add:[cells boundary]. The `ObservedProperties` Conformance Class defines how a base `ObservedProperty` is linked to the derived `ObservedProperty` of each aggregate function, and how that derived property is linked to the function advertised on the landing page. It requires the implementation to advertise each aggregate function with a definition identifier and a well-accepted mathematical equation, and to register entity linking. Create, Update, and Delete of a derived `ObservedProperty` are limited to the implementation itself and to an administrator. The `Aggregation` Conformance Class defines how an implementation calculates aggregate values from raw observations del:[linked to a cell] add:[whose `Datastream` s are linked to a cell]: the implementation is configured with aggregate intervals, and aggregation traverses from the finest resolution up to the coarsest resolutiondel:[, visiting all parents]. The optional `STAplus` Conformance Class applies when STAplus is enabled: del:[each aggregate `MultiDatastream` is owned by a `Party` whose `role` is `system`] add:[a `Party` associated with an aggregated `Datastream` or a `MultiDatastream` has `role` `system`, and an attribution license on an aggregate stream lists the contributing license identifiers in `attributionText`].

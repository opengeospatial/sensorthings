add:[This Standard adds the `PartyLocation` and `PartyActivity` entity types to the STAplus data model. Access to these entities via HTTP is defined in the Read, Create, Update, and Delete Requirements Classes. The use of MQTT is defined in the MQTT Requirements Classes. The retention of observer context is defined in the Lifecycle Requirements Class. The Default-CRS, Geometry-FG, and Geometry-WKT Requirements Classes of <<OGC22-022r2>> are extended so that they also apply to `PartyLocation/position`. The mandatory Landing Page Requirements Class requires the accepted geometry `encodingType` ValueCodes and the accepted `PartyLocation` `environment` EnvCodes to be advertised on the landing page. This Standard does not define access control, disclosure, or a legal basis for personal data. An implementation accepts `PartyLocation` and `PartyActivity` of a `Party` whose `role` is `individual` only if its advertised Business Logic states them (see <<req-party-context-party-role>>).]

del:[This OGC Standard defines two mandatory conformance classes, one conditionally mandatory conformance class, and several optional conformance classes.] add:[This OGC Standard defines two mandatory conformance classes and several optional conformance classes.]

Conformance with this Standard is to be checked using all the relevant tests specified in Annex A of this document and in Annex A of <<OGC22-022r2>>. The framework, concepts, and methodology for testing, and the criteria to be achieved to claim conformance are specified in the OGC Compliance Testing Policies and Procedures and the OGC Compliance Testing web site.

In order to conform to this OGC Standard, a software implementation can choose to implement:

* The mandatory conformance classes `Landing Page` and `Party Context`;
* del:[The `GDPR` Conformance Class if the implementation accepts a `Party` entity whose `role` is equal to `individual`;] add:[The Business Logic Conformance Class of <<OGC22-022r2>> if the implementation accepts `PartyLocation` or `PartyActivity` of a `Party` whose `role` is equal to `individual`;]
* Any of the optional conformance classes; and
* Pass all applicable tests as defined in Annex A of this document and in Annex A of <<OGC22-022r2>>.

del:[This is the list of STAplus 1.1 Conformance Classes.] add:[This is the list of Party Context Conformance Classes.]

* *Landing Page* (mandatory): This Conformance Class is introduced by this Standard. It requires the implementation to advertise the supported geometry `encodingType` ValueCodes for `FeatureOfInterest/feature`, `Location/location`, and `PartyLocation/position` as a JSON array on the landing page, and requires the implementation to advertise the accepted `environment` EnvCodes for `PartyLocation` as a JSON array on the landing page.

* *Party Context* (mandatory): This Conformance Class incorporates STAplus 1.0.1 Core and adds the Read of `PartyLocation` and `PartyActivity` via HTTP. It also extends the Default-CRS Requirements Class to `PartyLocation/position`. del:[If the implementation accepts a `Party` whose `role` is equal to `individual`, it also claims `GDPR`.] add:[It also specifies the retention of observer context.]

* *Create* (optional): del:[This Conformance Class supports creating STAplus 1.1 entities via HTTP.] add:[This Conformance Class supports creating `PartyLocation` and `PartyActivity` entities via HTTP. It also specifies the conditions under which `PartyLocation` and `PartyActivity` of a `Party` whose `role` is equal to `individual` are accepted.]

* *Update* (optional): del:[This Conformance Class supports updating STAplus 1.1 entities via HTTP.] add:[This Conformance Class supports updating `PartyLocation` and `PartyActivity` entities via HTTP. It requires the Create Conformance Class, whose requirement <<req-party-context-party-role>> also governs the Update of `PartyLocation` and `PartyActivity` of a `Party` whose `role` is equal to `individual`.]

* *Delete* (optional): del:[This Conformance Class supports deleting STAplus 1.1 entities via HTTP.] add:[This Conformance Class supports deleting `PartyLocation` and `PartyActivity` entities via HTTP, and deleting them together with their `Party`.] del:[*Authentication* (optional): This Conformance Class is inherited from <<OGC22-022r2>>.]

* *Geometry-FG* (optional): This Conformance Class extends the STAplus 1.0.1 Geometry-FG Requirements Class to `PartyLocation/position`.

* *Geometry-WKT* (optional): This Conformance Class extends the STAplus 1.0.1 Geometry-WKT Requirements Class to `PartyLocation/position`.

* *MQTT Subscribe STA v1.0* (optional): This Conformance Class supports a client to del:[receive STAplus 1.1 entity changes via MQTT as defined in <<OGC15-078r6>>.] add:[receive `PartyLocation` and `PartyActivity` entity changes via MQTT as defined in <<OGC15-078r6>>.]

* *MQTT Subscribe STA v1.1* (optional): This Conformance Class supports a client to del:[receive STAplus 1.1 entity changes via MQTT as defined in <<OGC18-088>>.] add:[receive `PartyLocation` and `PartyActivity` entity changes via MQTT as defined in <<OGC18-088>>.] del:[*Business Logic* (optional): This Conformance Class is inherited from <<OGC22-022r2>>, including the GDPR compliance note for `Location` and `HistoricalLocation` of an individual party's `Thing`, and the License attribution note that system `License` entities are templates and that each use is an instance with `attributionText` filled.] del:[*GDPR* (mandatory when any `Party` has `role` equal to `individual`; otherwise optional): This Conformance Class restricts Read, Create, Update, and Delete of `Location` and `HistoricalLocation` of a `Thing` owned by an individual `Party` to that authenticated party. It also restricts Read, Create, Update, and Delete of `PartyLocation` and `PartyActivity` to the authenticated party linked via the `Party` association, and specifies the personal-data lifecycle. Conformance to this class is not a certification of compliance with <<GDPR>>.] del:[*Sharing Party Context* (optional): This Conformance Class adds the `Share` entity. A valid `Share` grants named recipient parties Read, and optionally Update, of a `PartyLocation` or `PartyActivity` that the GDPR Requirements Class otherwise restricts to the owner.]

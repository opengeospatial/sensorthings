[requirement]
.Agreements restricted to applications
====
[%metadata]
identifier:: http://www.opengis.net/spec/sensorthings-staplus-gdpr/1.0/req/accepted-clients/client-restricted-agreements
part:: The implementation SHALL allow each del:[Agreement] add:[ReleaseProfile] to have the optional property `clientIds` listed in <<tab-releaseprofile-ac-properties>>. `clientIds` SHALL be immutable according to del:[<<req_gdpr_agreement-immutable>>] add:[<<req_gdpr_releaseprofile-lifecycle>>].
part:: The implementation SHALL reject with HTTP 400 the creation of del:[an Agreement] add:[a ReleaseProfile] whose `clientIds` is empty, contains a value for which its own catalog contains no Client entity with that `clientId`, or is present while `audience` is not `authenticated`.
part:: An Agreement del:[with] add:[whose ReleaseProfile has] `clientIds` SHALL be effective for a requester `r` only if, in addition to the conditions of <<req_gdpr_agreement-effective>>, the credential of the request of `r` resolves, as specified in <<req_accepted-clients_client-acceptance>>, to a client identification whose client identifier is contained in `clientIds` and which matches a Client entity whose `status` is `accepted`. For MQTT, the credential presented when the connection was established SHALL be used.
part:: For requests that read entities, the implementation SHALL resolve the client identification from the credential in the same way as for requests that create or update entities. A read request whose credential does not resolve to a client identification SHALL NOT be rejected for that reason; no Agreement del:[with] add:[whose ReleaseProfile has] `clientIds` is effective for it.
part:: A response that contains a value released on the basis of an Agreement del:[with] add:[whose ReleaseProfile has] `clientIds` SHALL carry the header `Cache-Control` with the directive `private` or `no-store`.
====

[[req_gdpr_release-resolution]]
[requirement]
.add:[Release resolution]
====
[%metadata]
identifier:: http://www.opengis.net/spec/sensorthings-staplus-gdpr/1.0/req/gdpr/release-resolution
part:: add:[For an indirect location property or an indirect time property with the path `p` of an entity attributable to a Party `P` whose `role` is `individual`, and a requester `r` that is not the data subject of `P`, the implementation SHALL determine the release resolution as follows. The grants are the ReleaseProfiles of the Agreements of `P` that are effective for `p`, the operation `publish` and `r`. If there is at least one grant, the release resolution is the smallest `locationResolution` (for a location property) or `timeResolution` (for a time property) of the grants, where a grant without that property counts as zero, the stored precision; if the corresponding generalization (`locationGeneralization` or `timeGeneralization`, see <<req_gdpr_advertisement>>) is advertised and its `resolution` is smaller, the release resolution is that `resolution`. If there is no grant, the release resolution is the advertised `resolution`; if the corresponding generalization is not advertised, the property is not released.]
part:: add:[The implementation SHALL then raise the release resolution to the `locationResolution` or `timeResolution` of every privacy area of `P` that applies to the value according to <<req_gdpr_privacy-areas>>, if that resolution is larger.]
part:: add:[If the release resolution is zero, the implementation SHALL release the stored value. If it is greater than zero and the corresponding generalization is advertised, the implementation SHALL release the generalized value computed at the release resolution according to <<req_gdpr_release-location>> or <<req_gdpr_release-time>>. Otherwise, the implementation SHALL omit the property if it is optional and SHALL withhold the entity if the property is mandatory, as indicated in <<tab-register>>.]
part:: add:[The implementation SHALL reject with HTTP 400 the creation of a ReleaseProfile that has `locationResolution` while `locationGeneralization` is not advertised, that has `timeResolution` while `timeGeneralization` is not advertised, or, if the implementation claims the DGGS conformance class, that has `locationResolution` or a member of `privacyAreas` with `locationResolution`; with that class, `zoneLevel` and `privacyZones` (<<req_dggs_releaseprofile-zone-level>>) apply to locations instead.]
part:: add:[This requirement SHALL apply to every response, including responses to requests with `$select`, `$expand` at any depth and navigation links, and to MQTT payloads.]
====

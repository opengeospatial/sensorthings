[[req_gdpr_mqtt]]
[requirement]
.MQTT
====
[%metadata]
identifier:: http://www.opengis.net/spec/sensorthings-staplus-gdpr/1.0/req/gdpr/mqtt
part:: del:[If the implementation claims the STAplus conformance class MQTT Subscribe STA v1.0 or MQTT Subscribe STA v1.1,] add:[If the implementation delivers entity changes via MQTT, whether under the STAplus conformance classes MQTT Subscribe STA v1.0 or MQTT Subscribe STA v1.1, under the MQTT Subscribe conformance classes of <<OGC26-040>>, or under the capability to receive updates via MQTT of <<OGC15-078r6>> or <<OGC18-088>> for the SensorThings entity types,] the requirements <<req_gdpr_agreement-access>>, <<req_gdpr_release-direct>>, <<req_gdpr_release-free-text>>, <<req_gdpr_release-location>>, <<req_gdpr_release-time>>, <<req_gdpr_attribution-integrity>>, <<req_gdpr_relation-release>> and <<req_gdpr_campaign-participation>> SHALL apply to every MQTT message payload as to an HTTP response for the subscribing MQTT client.
part:: An MQTT client that is not authenticated SHALL be treated as an unauthenticated requester. An authenticated MQTT client SHALL be treated as the user it is authenticated as.
part:: A message about an entity that is withheld for the subscribing client SHALL NOT be delivered to that client.
part:: add:[This requirement SHALL apply to every topic through which the implementation delivers entity changes, including the topics of the SensorThings entity types, for example `Things`, `Locations`, `HistoricalLocations`, `Datastreams(...)/Observations` and `FeaturesOfInterest`, and topics with `$select`. Claiming none of the MQTT Subscribe conformance classes of STAplus or of <<OGC26-040>> SHALL NOT exempt MQTT messages from this requirement.]
====
